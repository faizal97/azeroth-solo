# Friends Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Real players add each other by friend code and see each other's shared characters, gear and online
status live (design: `docs/plans/2026-09-30-friends-design.md`).

**Architecture:** `src/friends.js` (`FRIENDS`) holds all the logic against a small backend interface, so a fake
backend in `sim/friends.js` can test every flow in Node. The real backend loads the Firebase SDK (Auth, Firestore
in Jakarta, Realtime Database in Singapore) from gstatic only once Friends is on. Security rules live in
`firebase/` and are tested against Firebase's local emulator. The UI is a Friends tab in Social (`src/ui.js`).

**Tech stack:** plain browser JS (no bundler), Firebase JS SDK 12.19.0 modular from gstatic, Node sims,
`firebase-tools` + `@firebase/rules-unit-testing` (dev only, in `firebase/`), Java 21 or newer for the emulator (Homebrew openjdk, 26); the Android build keeps openjdk@17.

**Rules for the executor:** never push, publish rules, or release without Faizal's yes. Keep old saves loading.
Mob and item ids never change. Run `python3 build.py` before calling anything done (it runs every check).

**Step 3: `firebase/firestore.rules`**

```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    function me() { return request.auth != null ? request.auth.uid : ''; }
    function only(keys) { return request.resource.data.keys().hasOnly(keys); }
    function friendOf(owner) { return exists(/databases/$(db)/documents/friends/$(owner)/list/$(me())); }

    match /codes/{code} {
      allow get: if me() != '';
      allow create: if me() != '' && code.matches('^[2-9A-HJKMNP-Z]{8}$') && only(['uid']) && request.resource.data.uid == me();
      allow delete: if resource.data.uid == me();
    }
    match /profiles/{uid} {
      allow read: if me() == uid || (me() != '' && friendOf(uid));
      allow create, update: if me() == uid && only(['v', 'code', 'updatedAt', 'lastSeen', 'playing', 'chars'])
        && request.resource.data.v is int && request.resource.data.chars is map && request.resource.data.chars.size() <= 12;
      allow delete: if me() == uid;
    }
    match /requests/{to}/in/{from} {
      allow read, delete: if me() == to || me() == from;
      allow create: if me() == from && from != to && only(['name', 'cls', 'level', 'at'])
        && request.resource.data.name is string && request.resource.data.name.size() <= 24;
    }
    match /friends/{owner}/list/{other} {
      allow read: if me() == owner || me() == other;
      allow create: if only(['since']) && (me() == owner
        || (me() == other && exists(/databases/$(db)/documents/requests/$(other)/in/$(owner))));
      allow delete: if me() == owner || me() == other;
    }
  }
}
```

Note for case 4: amy (the receiver) accepts ben's request `requests/amy/in/ben`. She is the owner of her own list,
and she writes `friends/ben/list/amy` as `other` = amy with `requests/amy/in/ben` present: the rule's
`requests/$(other)/in/$(owner)` is `requests/amy/in/ben`. ✓ In a batch, `exists()` sees the state before the batch,
so deleting the request in the same batch is fine.

**Step 4:** `npm test`. Expected: all Firestore cases pass.

### Task 4: `FRIENDS` core, test first

**Files:** Create `src/friends.js`, `sim/friends.js`; modify `build.py` (add `src/friends.js` after `src/cloud.js`,
and run `sim/friends.js` after `sim/cloudsync.js`).

`sim/friends.js` loads the game data and `game.js` like `sim/cloudsync.js`, gives each fake player its own
`localStorage`, and installs `FRIENDS.setBackend(fake)` where the fake holds both databases in `Map`s and applies the
same checks as the rules (so a flow that would break the rules fails in the sim too).

**Pure helpers (tests first, then code):**
- `FRIENDS.newCode(rand)`: 8 characters from `23456789ABCDEFGHJKMNPQRSTUVWXYZ`; shown as `K7QM-P2XD`;
  `FRIENDS.cleanCode(text)` accepts either form, lowercase, spaces, and a whole share link.
- `FRIENDS.charCard(S)`: the shared view of one saved character: `name, race, cls, look: [gender, skin, hair],
  level, role (player.role or the class role), talents, profs (id → skill), guild ({name, rank} or null), title,
  mounts (count), gear (the equipped items as saved), at`. `null` when `S.player.friendsHidden`.
- `FRIENDS.playing(S)`: `{ char, zone, place, run }` from `player.place` and `S.run`, or `null` when hidden.
- The writer: `FRIENDS.touch(id)` marks a character changed; `FRIENDS.flush(force)` writes at most once a minute
  (`force` on going to the background), only the changed `chars.<id>` fields plus `playing`, `lastSeen`,
  `updatedAt`; a hidden or deleted character becomes a field delete.

**Flows (tests first):** `turnOn` (sign in; code created once and kept in the profile; publish every local
character), `turnOff` (delete profile, status, `see`, sent requests; keep code and friendships), `deleteAll`,
`add(code)` (look up; refuse your own code, an unknown code, an existing friend; create the request),
`accept(from)` (batch: both list entries, delete request), `decline`, `cancel`, `remove(other)` (both entries and
both `see` sides), `repairSee()` (make `see/me` equal to `friends/me/list`), `setShared(id, on)`.

Sim cases: two players add, accept, see each other's profile; a stranger cannot; hiding a character removes it and
blanks `playing`; the browser with fewer characters never removes the phone's; the writer gathers ten changes into
one write; `turnOff` then `turnOn` restores friends; `remove` cuts both ways; a broken `see` list is repaired.

**Commit** after the helpers, and again after the flows.
